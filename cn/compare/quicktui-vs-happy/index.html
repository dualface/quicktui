QuickTUI 对比 Happy

QuickTUI 和 Happy 都能让你在手机上运行编码智能体，但它们的出发点不同。Happy 是一款专注于 Claude Code 的移动客户端；QuickTUI 是一个完整的 tmux 终端，能运行任何 CLI 智能体，默认自托管、直连。

如果你的整个移动工作流就是 Claude Code，Happy 的专注让一切保持简单。QuickTUI 走的是更宽广的路线： 它接入你自己服务器上的真实 tmux，因此你能获得窗口、窗格和回滚缓冲，并且可以在一个断线后依然存活的会话 里运行 Claude Code、Codex 或其他任何东西。

单一智能体 vs 任意终端

Happy 是围绕在手机上运行 Claude Code 构建的，一个专注的客户端处理这一件事可能感觉更清爽。QuickTUI 首先是一个真正的终端：凡是你能在 shell 里运行的（Claude Code、Codex、一次构建、一段日志跟踪、一跳 SSH），你都可以在跨越多个 tmux 窗口的并排布局中运行并监督它。

你的代码在哪里

QuickTUI 默认自托管、直连，因此你的代码和密钥只停留在你的手机与你自己的服务器之间。如果这种掌控对你 重要，它是一项核心设计选择，而非附加功能。配对只需扫一个二维码，同一个实时会话会出现在 iPhone、iPad 和浏览器上。

保持接入

因为 QuickTUI 驱动 tmux，你的会话能在连接掉线和网络切换中存活，因此你能从离开的地方精确地重新接入。 这份会话保持正是你所选择的一部分。

你该选哪个？

如果手机上的 Claude Code 基本上就是你的全部使用场景，而你又喜欢一个为它量身打造的客户端，那么 Happy 可能很适合你。如果你想要一个真正的 tmux 终端、运行任意智能体的自由、自托管直连，以及一个跨断线持续存活 的会话，那么 QuickTUI 更契合。

常见问题

QuickTUI 能像 Happy 那样运行 Claude Code 吗？

能。你在自己服务器上的一个 tmux 会话里启动 Claude Code，并从应用中驱动它，你还可以在同一个终端里运行 Codex 或任何其他 CLI 智能体。

QuickTUI 是自托管的吗？

是。QuickTUI 默认直连你自己的服务器，因此你的代码和密钥不会经由我们的基础设施中转。
