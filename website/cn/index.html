§ 01 / 增强能力展示

舒适、高效

每一项功能，都为移动设备精心打造。

D.01

终端

从自动断线重连、会话恢复、自适应布局，到快速输入与复制粘贴，所有细节都针对移动设备做了充分优化，提供最舒适的使用体验。

D.02

Agent 向导

快速启动各种 Agent，无需再手动输入命令来选择模型和推理等级。在设置界面里添加自定义参数组合，随时复用。

D.03

会话管理器

展示电脑上所有的 tmux 与 Herdr 工作区和会话，让你可以快速跳转。新建、重命名、关闭等常用功能也样样具备。

D.04

文件管理器

浏览电脑上的文件，预览图片、Markdown 和代码。下载电脑文件或者上传文件到电脑，都可以在文件管理器中完成。还支持压缩与解压，以及快速切换目录的收藏夹。

D.05

端口转发

自动扫描电脑上打开的 Web 服务等端口，用内置浏览器预览页面。Agent 的改动立即就可以看到效果。再也不用依赖缓慢的远程桌面工具。

D.06

命令面板

支持绝大多数 Agent 和各种常用终端操作的命令入口，无需查阅命令行参数，直接快速输入到 Agent 或终端。目前已添加超过 500 个命令。命令清单自动更新，还能在设置界面中自定义。

D.07

输入栏

支持语音输入、附件上传，编辑好内容一次性发送给终端。高效、易用。

D.08

快捷栏

最多可以堆叠三个完全自定义的快捷栏，用于执行命令、发送组合键、打开功能 UI 等高频操作。

§ 02 / 常见问题

常见问题。

最常被问到的问题。完整文档见 FAQ 专页。

Q.01
为什么要使用 Herdr 或 tmux？

Herdr 和 tmux 都支持多个工作区，并能让会话在后台持续运行：只要电脑没有重启，你的 Agent 会话就会一直保持。

对于大多数用户，推荐使用 Herdr：它与 Agent 的集成更好，性能也更出色。如果你已经习惯 tmux，QuickTUI 同样完整支持 tmux。

+
Q.02
如何安装 Herdr？
# macOS / Linux
curl -fsSL https://herdr.dev/install.sh | sh

# Windows（PowerShell）
powershell -ExecutionPolicy Bypass -c "irm https://herdr.dev/install.ps1 | iex"

完整文档：herdr.dev/docs/install

+
Q.03
如何安装 tmux？

多数 Linux 发行版可以直接用包管理器安装，macOS 可以用 Homebrew：

# Debian / Ubuntu
sudo apt install tmux

# Fedora
sudo dnf install tmux

# macOS（Homebrew）
brew install tmux

QuickTUI 需要 tmux 3.2 及以上版本。其他系统见 tmux 安装文档。

tmux 不支持 Windows，Windows 上请使用 Herdr。

+
Q.04
重新运行安装脚本会发生什么？

安装命令会原地升级已有的服务端：用新版本替换 QuickTUI 服务端并重启服务，替换失败时自动恢复原版本。

已配对的设备、服务端身份和现有配置（端口、会话后端等）都会保留，无需重新配对。

+
Q.05
如何配对另一台设备？

在电脑上运行配对引导：

# macOS / Linux
~/.local/bin/quicktui-server pairing welcome

# Linux（以 root 安装）
sudo /usr/local/bin/quicktui-server pairing welcome

# Windows（PowerShell）
quicktui-server pairing welcome

按引导选择显示二维码的方式：推荐在桌面浏览器中显示；也可以直接在终端中显示，但部分终端字体可能导致二维码无法识别。

二维码出现后，在 App 中：

  1. 在服务器列表点 +。
  2. 选择 其他连接方式。
  3. 选择 扫描二维码连接已启用增强功能的电脑，点 下一步。
  4. 将摄像头对准二维码，完成配对。
+
Q.06
可以通过公网连接吗？

可以。任选一种方式，让手机能访问到你的电脑：

QuickTUI Relay
可选订阅，在 App 里开通即可，无需任何网络配置。
VPN
例如 Tailscale，手机和电脑处在同一个虚拟网络里即可直连。
隧道或反向代理
例如 Cloudflare Tunnel 或带 TLS 的反向代理，指向 http://127.0.0.1:8022，然后在 App 里填写公网 HTTPS 域名（不带 :8022）。

配对码、设备登录和你的所有操作都在端到端加密隧道里传输，即使直接开放 8022 端口，别人也无法窃听内容或冒充你的电脑。不过直接开放时，外界能看到这里运行着 QuickTUI 及其版本号等少量信息，大量恶意连接也可能让你自己的设备暂时连不上，所以更推荐上面几种方式。

通过隧道或反向代理配对时，先把 QuickTUI 服务端更新到最新版，再生成带公网地址的配对二维码：

# macOS / Linux
~/.local/bin/quicktui-server pairing qrcode --public-url https://your.domain

# Windows（PowerShell）
quicktui-server pairing qrcode --public-url https://your.domain

隧道或反向代理需要保留原始 Host 请求头，并发送 X-Forwarded-Proto；Cloudflare Tunnel 默认两者都满足。如果你的代理不发送该请求头，还需要把 QuickTUI App 更新到最新版。

配对二维码短期有效，请勿泄露。

+
Q.07
QuickTUI 如何认证设备？

QuickTUI 通过设备配对来认证，全程端到端加密：

配对时
配对二维码里包含一次性配对码和电脑的身份指纹。配对码 15 分钟内有效、只能用一次，而且只在加密通道里传输。App 会记住电脑的身份，之后只连接身份一致的电脑，别人无法冒充。
设备密钥
每台手机在配对时生成自己的密钥，私钥保存在系统安全存储里（iPhone 的安全隔区或钥匙串，Android 的 Keystore），不会离开手机。
每次连接
App 先核对电脑身份，再用设备私钥证明自己是已配对的设备，双方为这次连接协商出全新的加密密钥。终端、文件、端口转发等所有数据都经过加密，并有防重放保护。
经 Relay 转发时
QuickTUI Relay 只转发加密后的数据，看不到内容，也无法冒充任何一方。唯一的例外是推送通知：开启后，Relay 在投递时会短暂看到通知文字。
撤销设备
手机丢失或不再使用时，在电脑上撤销它：
# 列出已配对设备
~/.local/bin/quicktui-server pairing devices list

# 撤销指定设备
~/.local/bin/quicktui-server pairing devices revoke <设备 ID>

撤销后，该设备最迟 5 分钟内被断开，之后无法再连接。Windows 请在 PowerShell 中运行同样的命令，以 quicktui-server 开头。

+
Q.08
无法连接 — connection refused。

先确认服务端正在运行：

# macOS
launchctl print gui/$(id -u)/ai.quicktui

# Linux
systemctl --user status quicktui

# Linux（以 root 安装）
systemctl status quicktui

# Windows（PowerShell）
Get-Process quicktui-server

没有运行就重启服务：

# macOS / Linux
~/.local/bin/quicktui-server service restart

# Linux（以 root 安装）
sudo systemctl restart quicktui

# Windows（PowerShell）
quicktui-server service restart

服务在运行但仍然被拒绝时，请确认防火墙、VPN 或隧道放行了服务端端口（默认 8022）。

+
Q.09
Linux 上退出登录后，服务端就停止了？

Linux 普通用户安装的服务端以 systemd 用户服务运行，默认随登录会话启停。关闭 SSH 连接或退出登录后，服务端可能随之停止，手机将无法连接。开启 linger 即可常驻运行，根据情况选择对应的命令：

1. 直接开启（本机登录或当前用户有权限时）：

loginctl enable-linger

2. 提示权限不足（如 Access denied、Interactive authentication required，常见于 SSH 远程登录）。有 sudo 权限时：

sudo loginctl enable-linger "$USER"

没有 sudo 权限时，请管理员代为执行：

sudo loginctl enable-linger <你的用户名>

3. 提示 Failed to connect to bus。如果是用 su 或 sudo -u 切换到该用户后运行的，当前会话缺少用户总线，请改为直接以该用户 SSH 登录后再运行；或先补上运行时目录再开启：

export XDG_RUNTIME_DIR=/run/user/$(id -u)
loginctl enable-linger
systemctl --user restart quicktui

如果系统本身没有以 systemd 启动（部分容器、未启用 systemd 的 WSL），用户服务和 linger 都无法使用，请改用 root 安装，或先为系统启用 systemd。

确认已开启：输出 Linger=yes 即可。

loginctl show-user "$USER" --property=Linger

开启后服务端会开机自启并常驻运行，与是否登录无关。以 root 安装的系统服务不受此影响。
